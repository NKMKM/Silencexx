# Qwen API и экономика CloudMind

Изменения внесены в обе копии backend. Чат, дневник, анализ настроения, ежедневные пожелания и модерация пожеланий используют официальный Alibaba Cloud Model Studio. Модель по умолчанию — `qwen-flash`, Singapore / International, без thinking. Whisper продолжает распознавать голос локально: текстовая модель не заменяет распознавание аудио.

## Подключение

1. Зарегистрируйся в [Alibaba Cloud Model Studio](https://modelstudio.console.alibabacloud.com/), выбери **Singapore** и создай обычный **pay-as-you-go API key** в разделе API Key. Ключ Coding Plan/Token Plan для этой интеграции не подходит. [Инструкция провайдера](https://www.alibabacloud.com/help/en/model-studio/get-api-key).
2. В `.env` запускаемой копии backend добавь:

```dotenv
QWEN_API_KEY=твой_ключ
QWEN_WORKSPACE_ID=идентификатор_workspace
QWEN_MODEL=qwen-flash
AI_ADMIN_USER_IDS=твой_числовой_id_пользователя
```

Workspace ID возьми из консоли/API Host. Можно вместо него задать `QWEN_BASE_URL` — HTTPS endpoint из консоли с суффиксом `/compatible-mode/v1`, без `/chat/completions`. Регион ключа должен совпадать с endpoint. Рекомендуется workspace endpoint: `https://WORKSPACE_ID.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1`. Без workspace используется прежний международный endpoint. [Формат запросов и адреса](https://www.alibabacloud.com/help/en/model-studio/compatibility-of-openai-with-dashscope).

3. В каталоге выбранного backend: `npm install`, `npm run build`, перезапусти сервер привычным способом. Код сам создаёт `ai_usage`; DB-пользователю нужны права CREATE TABLE/INDEX. Если права ограничены, выполни схему из `src/aiUsage.ts` через администратора до запуска.

Ключ хранится только на сервере в игнорируемом `.env`. Без ключа AI-запрос завершается ошибкой, подставных ответов нет. Тесты не используют реальный API и не тратят деньги. Ускорение пока не измерено: для измерения нужны ключ, работающий backend и реальные запросы. Сокращены повторяемые инструкции, история ограничена 12 сообщениями и общим бюджетом 24 000 символов, ответ — 512 токенами. Символы не равны токенам. Ограничение ответа может обрезать длинные ответы. Потоковый вывод не добавлен.

## Токены и расходы

На 07.10.2026 для Singapore International `qwen-flash`, вход до 256K токенов: **$0.05 за 1M входных, $0.40 за 1M выходных, $0.01 за 1M закэшированных провайдером входных**. Источник: [тариф модели](https://www.alibabacloud.com/help/en/model-studio/qwen-flash). Тарифы фиксируются в каждой записи; после изменения тарифа обнови переменные `QWEN_*_USD_PER_MILLION` в `.env`. При другой модели/регионе обязательны все три цены. Контекст ограничен для использования начального тарифного диапазона.

`cost = ((input − cached_input) × 0.05 + cached_input × 0.01 + output × 0.40) / 1 000 000`.

Записываются фактические значения `usage` от API: input, output, cached input, reasoning, user ID, функция, модель, request ID, задержка, статус, оценка стоимости. Reasoning уже входит в output и второй раз не оплачивается в формуле. История и системный промпт входят во входные токены при каждом запросе. Некорректный ответ также может стоить денег и учитывается.

`served_output_tokens` — токены текста, доступного обработчику приложения или повторно взятого из кэша. Это не доказательство доставки/прочтения пользователем; обработчик может отклонить JSON после генерации. При кэше приложения новые оплаченные токены и стоимость — ноль, а повторно доступный текст учитывается отдельно. Кэш провайдера — другое: вход оплачивается по льготной ставке. Сохранённое пожелание дня при повторном запросе не вызывает AI и не создаёт новую запись расхода.

Таймауты, потерянные ответы и отсутствующий `usage` имеют неизвестную стоимость: их нельзя считать бесплатными. Запись pending создаётся до платного вызова; при отказе DB вызов не отправляется. Если финальная запись в DB не удалась, только метаданные сохраняются в `.ai-usage/recovery.ndjson` (без ключей, промптов и ответов). После восстановления DB: `npm run usage:recover`, затем сверка отчёта. Файл оставлен для аудита; повторное применение идемпотентно. Итоговый счёт Model Studio приоритетнее оценки приложения.

- `GET /api/ai/usage?days=30` с Bearer JWT — только собственная статистика.
- `GET /api/ai/usage?days=30&scope=all` — общая статистика только для ID из `AI_ADMIN_USER_IDS`.
- `npm run usage:report -- 30` — отчёт владельца сервера по пользователям и функциям.
- `npm run economics` — воспроизводимый расчёт сценариев.
- `node scripts/economics.js path/to/scenario.json` — заменить предположения параметрами JSON из `defaults` в скрипте.

Отчёт не выводит пользовательские тексты. При нескольких экземплярах backend возможны одновременно оплаченные генерации одного пожелания; первым сохранённым текстом пользуются все повторные запросы пользователя за этот день. Все вызовы учитываются. Внутри одного процесса такие запросы объединяются.

## Сценарии на месяц, USD

Это предположения, а не текущая прибыль. 1 000 активных пользователей; 30 дней; бесплатный пользователь — 5 сообщений/день, платный — 20; каждое сообщение в среднем 2 000 входных и 350 выходных токенов; 1 пожелание и 1 анализ настроения/день, 0.2 анализа дневника/день. Параметры вспомогательных запросов указаны в `scripts/economics.js`. Кэш-скидки не предполагаются. Одно сообщение стоит **$0.00024**, AI за месяц — **$0.0396 на бесплатного / $0.1476 на платного** при этих нагрузках.

Комиссия магазина в сценарии — 15%; фиксированные расходы — условные $50/месяц.

| Подписка | Платят | Выручка | AI | Остаток после магазина, AI и $50 |
|---|---:|---:|---:|---:|
| $4.99 | 1% (10) | $49.90 | $40.68 | −$48.27 |
| $4.99 | 5% (50) | $249.50 | $45.00 | $117.08 |
| $4.99 | 10% (100) | $499.00 | $50.40 | $323.75 |
| $9.99 | 1% (10) | $99.90 | $40.68 | −$5.77 |
| $9.99 | 5% (50) | $499.50 | $45.00 | $329.58 |
| $9.99 | 10% (100) | $999.00 | $50.40 | $748.75 |

Условный порог безубыточности: около 2.17% платящих при $4.99 и 1.07% при $9.99. При комиссии 30%, цене $4.99 и 5% платящих остаток падает до $79.65. При 50/200 сообщениях в день AI одного платного пользователя стоит $0.3636/$1.4436 в месяц с теми же токенами. При длинном контексте 12 000 входных и 512 выходных — $0.0008048/сообщение; 200 сообщений/день дают около $4.83 только за чат, что уже превышает $4.24 после комиссии с подписки $4.99.

15% не гарантированы для любого приложения: Apple требует соответствия и участия в [Small Business Program](https://developer.apple.com/app-store/small-business-program/); у Google auto-renewing subscriptions имеют [комиссию 15%](https://support.google.com/googleplay/android-developer/answer/112622?hl=en). Фактическая комиссия зависит от условий и схемы продажи.

Не включены реальные расходы на Whisper/голос/TTS, хранение, трафик, мониторинг, поддержку, разработку, возвраты, налоги и привлечение. Их нужно заполнить через `otherVariablePerUser`, `acquisitionAmortizedPerUser`, `taxRate`, `paymentFee`, `fixedCosts`. Например, $1 ежемесячно амортизированных расходов на привлечение каждого из 1 000 пользователей превращает +$117.08 в −$882.92. Процент налогов в калькуляторе условно применяется к gross, его нужно адаптировать под фактическую базу.

В текущей БД есть тарифы 299/599 RUB и тестовая логика оплаты. Эти значения не являются подтверждённой выручкой и не заменены на долларовые. Расчёт выше относится к будущим подпискам; настоящая прибыль требует подтверждённых платежей/отчётов магазинов и фактических расходов. Прибыль = подтверждённый доход после комиссий и возвратов − все расходы. Из токенов можно определить расход AI, но не доход.
