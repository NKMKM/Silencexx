## 🧪 Как протестировать

### 1. Запись и отправка голосового сообщения
```
1. Откройте приложение
2. Перейдите в чат
3. Нажмите кнопку микрофона 🎤
4. Скажите что-нибудь (1-5 секунд)
5. Нажмите "Отправить голос"
6. Проверьте: сообщение появилось с кнопкой Audio Player 🎵
```

**Ожидаемый результат:**
- ✅ Аудиофайл записан в: `/var/mobile/Containers/Data/Application/.../recording-[UUID].wav`
- ✅ Сообщение отправлено на сервер вместе с audioUri
- ✅ В чате видна кнопка AudioPlayer (🎵 или ▶️)

### 2. Загрузка истории голосовых сообщений
```
1. Закройте приложение полностью (kill от памяти)
2. Откройте приложение заново
3. Перейдите в тот же чат
4. Дождитесь загрузки истории
5. Проверьте: старые голосовые сообщения там с кнопками Audio Player
```

**Ожидаемый результат:**
- ✅ Backend вернул audio_uri из БД
- ✅ Frontend правильно распарсил и отобразил
- ✅ AudioPlayer кнопки видны для голосовых сообщений

### 3. Воспроизведение голосового сообщения
```
1. Нажмите на кнопку Audio Player (▶️) на любом голосовом сообщении
2. Слушайте аудио
3. Проверьте: прогресс бар движется правильно
4. Нажмите stop - аудио останавливается
```

**Ожидаемый результат:**
- ✅ Аудио воспроизводится через динамик
- ✅ Прогресс бар показывает позицию воспроизведения
- ✅ Можно остановить и воспроизвести снова

## 🔍 Отладка

### Если голосовые сообщения не сохраняются в БД

**Проверьте консоль сервера:**
```
✅ [abc123] POST /api/chat - NEW REQUEST
✅ [abc123] Saving messages to chat 5
✅ [abc123] Messages saved to database
```

### Если audio_uri не загружается из истории

**Проверьте:**
1. База данных имеет колонку audio_uri (запустите `npm run migrate` еще раз)
2. Frontend получает audio_uri из backend (смотрите Network tab в DevTools)
3. Сообщения правильно отображаются с audioUri

### Если AudioPlayer не работает

**Проверьте:**
1. audioUri имеет правильный формат: `file:///path/to/recording.wav`
2. VoiceRecorder сервис может прочитать файл
3. Разрешения доступа в приложении правильные
