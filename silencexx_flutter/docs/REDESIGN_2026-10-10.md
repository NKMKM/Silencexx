# CloudMind — обновление интерфейса, 10 октября 2026

## Область работы и аудит

Переработан существующий Flutter-клиент. Референсы из запроса использованы как структурные ориентиры: адаптивная навигационная панель, контекстное меню действий, пошаговые сценарии и асимметричная dashboard-композиция. Исходная структура приложения сохранена: MaterialApp, AppScope/AppState (ChangeNotifier), отдельный ChatWorkspace и ConversationSession, Navigator/MaterialPageRoute, локальные контроллеры форм. В проекте есть iOS, Android и web; отдельного macOS/Windows runner нет. Широкие адаптивные раскладки проверяются widget-тестами, это не подтверждение нативной desktop-сборки.

### Функциональные зависимости

API и bearer-авторизация остаются в Api/AuthService. Токен хранится через flutter_secure_storage; настройки, язык, порядок меню и метаданные чатов — через SharedPreferences. Напоминания используют flutter_local_notifications/timezone, виджет домашнего экрана — существующий native bridge. record/audioplayers/flutter_tts, image_picker/file_selector/share_plus и OAuth-плагины не заменялись. Контракты backend, данные PostgreSQL и нативный виджет не менялись в рамках редизайна. Mock-данные используются только в автоматических тестах.

## Дизайн-система

- Централизованы фон #08080D, графитовые поверхности, фиолетовый #8247FF, акцентные и статусные цвета.
- Сохранены светлая тема, русский/английский язык и системные шрифты. Новых зависимостей и сетевой загрузки шрифтов нет.
- Текстовые токены и градиент основной кнопки проверяются тестами на контраст; это проверка конкретных пар цветов, не сертификация всего приложения по WCAG.
- Кнопки имеют область нажатия минимум 48px в общей теме; специализированные небольшие действия чата сохраняют существующие размеры.
- Обычные GlassSurface рисуются градиентами и границами, без BackdropFilter. Опциональный blur ограничен 6px, в high contrast отключён. Размытие всего экрана под диалогом удалено.
- Карточки, ввод, диалоги, меню и навигация используют общую тему и существующие компоненты, без замены архитектуры.

## Движение и производительность

- Смена разделов сохраняет уже открытые страницы и черновики; неактивные ticker выключены.
- Нижняя навигация скрывается при клавиатуре, высота учитывает text scaling. На широком экране используется существующая боковая панель.
- Фон чата запускает ticker только при ожидании ответа/записи; останавливается в idle, фоне приложения, offstage и reduced motion.
- Переходы, нажатия и выбор настроены через AppMotion; упругая кривая без избыточного отскока.
- ActionButton сохраняет async guard и видимый индикатор загрузки; reduced motion отключает смену иконок.
- Нет постоянно анимируемых градиентов на всех экранах, нет новых тяжёлых графических зависимостей.

### Как повторить скриншоты

После настройки локального Flutter SDK тестовый прогон, который создаёт скриншоты и проверяет экраны:

```sh
flutter test test/design_test.dart \\
  --dart-define=DESIGN_REVIEW_DIR="$PWD/build/structural-after" \\
  --dart-define=DESIGN_REVIEW_FONT=/path/to/Roboto-Regular.ttf
node tool/make_screenshot_gallery.js "$PWD/build"
```

Первый проход, сохранённый в `build/structural-before`, — более ранняя версия приложения до структурной перестройки. Размеры viewport в названиях совпадают, но набор фиктивных данных и text scaling в некоторых парах различается (особенно на ширине 320px, где новая матрица дополнительно проверяет 200% текста). Поэтому серые пары показывают устройство экранов, а не контролируемый пиксельный benchmark.

Воспроизведение:

```sh
dart format lib test tool
flutter analyze
flutter test --reporter expanded
flutter run --profile -t tool/profile_ui.dart -d <device-id>
```

Профильный entrypoint запускает настоящий main и собирает FrameTiming в течение 90 секунд (до 4000 кадров). Он выводит только агрегаты времени build/raster, не содержимое пользователя. Обычная сборка из lib/main.dart этот инструмент не включает. P95 и число кадров длиннее бюджетов 60/120Hz не равны измерению FPS всего приложения; охват зависит от реально выполненных действий.

## Известные ограничения вне визуального редизайна

- API по умолчанию использует текущий ngrok-адрес; постоянная доступность внешнего backend не обеспечивается UI.
- UI тарифа сохраняет существующие единицы/валюту backend; экономика Qwen в USD не меняет контракт платежей автоматически.
- Имеются предупреждения Flutter/Xcode о будущем требовании UIScene и поддержке Swift Package Manager некоторыми плагинами. Миграция жизненного цикла не делалась ради визуальных изменений.
- Android release signing в проекте по-прежнему использует debug-конфигурацию; выпуск в Google Play требует отдельной настройки подписи.
- Реальные покупки, OAuth, голос, push/local notification delivery и обновления домашнего виджета требуют отдельных end-to-end проверок. Прежний аудит backend остаётся отдельным документом.
