# Пустая локальная PostgreSQL на Ubuntu/Debian

Скрипт запускается от root в уже развёрнутом backend. Он устанавливает PostgreSQL через apt, включает автозапуск, создаёт отдельные `cloudmind_local` и `cloudmind_local_app` (не superuser), UTC, применяет схему из `scripts/bootstrap-local.sql` одной транзакцией. Отказывается изменять уже существующую целевую БД/роль. TCP ожидается только на loopback и порту 5432; публичный порт не открывается.

Перед запуском нужны `.env`, `dist/server.js`, установленный пакет `pg` и `scripts/check-db.js`. Запуск:

```bash
cd /var/backend
bash scripts/provision-local-postgres.sh
```

Пользователи, чаты и дневник не переносятся. В схеме присутствуют только справочники языков и тарифов. Секрет пароля генерируется локально и не выводится. `.env` сохраняется с правами 600; исходный `.env.before-local-db.*` также содержит секреты и исключён из Git. Настройки Qwen/OAuth/почты сохраняются. JWT_SECRET меняется, чтобы токены старой БД не могли использовать совпадающие числовые ID новых аккаунтов/сессий. Потребуется повторная регистрация/вход.

Сервис `cloudmind` перезапускается, затем выполняется read-only DB-аудит. При ошибке перезапуска/аудита исходный `.env` восстанавливается. Обычный `/health` отдельно не доказывает подключение к БД. Логи аудита: `/tmp/cloudmind-local-db-check.log`. Cloudflare-туннель не перезапускается.

## Схема и порядок

Схема собрана из flyway/1..6 и актуальных migrations в порядке зависимостей: chat improvements до temporary/fix_schema; subscriptions до цен и tier_id. Из unified messages исключён DROP TABLE. Из индексов для пустой БД убран CONCURRENTLY, чтобы применять всё одной транзакцией. Проблемная legacy add_tier_id.sql заменена добавлением ссылки на уже существующие канонические тарифы, без конфликтующего повторного seed. Включены daily_wishes и ai_usage, обычно создаваемые при первом запросе.

## Проверено

- `bash -n scripts/provision-local-postgres.sh`.
- SQL выполнен в отдельном PostgreSQL WASM (PGlite), не на сервере: создано 27 таблиц; только free/plus/pro; users пустая.
- Выполнены тестовые INSERT регистрации, сессии, чата, современных сообщений и дневника.
- Повторный запуск на непустой схеме отклонён; сообщение сохранилось.

Установка apt, systemd, сетевое подключение и права PostgreSQL требуют проверки непосредственно на сервере. Из текущей рабочей среды SSH к 178.236.246.99:22 завершается тайм-аутом; удалённое выполнение не заявляется.

## Откат настроек

Если после успешного развёртывания нужен возврат к прежней БД, выберите сохранённый `.env.before-local-db.*`, скопируйте его в `.env`, восстановите права 600 и перезапустите `cloudmind`. Локальная БД при этом не удаляется. Не запускайте старые setup-db.js или run-migrations.js: они удаляют таблицы либо подавляют ошибки и не предназначены для такого переключения.
